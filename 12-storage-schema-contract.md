# MemoryGraph Storage Schema Contract

**Status:** Proposed v0 schema  
**Date:** August 21, 2026  
**Depends on:** `08-memorygraph-project-spec-v2.md` and `09-dream-cycle-protocol.md`  
**Purpose:** Remove ambiguity before implementation. Migration files may split this DDL, but must preserve its constraints and semantics.

---

## 1. Conventions

- UUIDs are lowercase canonical text generated by the application.
- Times are UTC ISO 8601 strings with a `Z` suffix and fixed microsecond policy.
- Time intervals are half-open: `[from, to)`.
- JSON text must pass `json_valid`.
- Boolean values are integers constrained to `0` or `1`.
- Every bank-owned foreign key includes `bank_id` to prevent accidental cross-bank relationships.
- Authoritative rows are never physically deleted during ordinary revision. Privacy deletion follows the explicit deletion workflow.
- SQLite foreign keys are enabled on every connection.

## 3. Search Index Contract

Use one normalized search document table and FTS5 external-content index. Application/repository code updates it inside the same transaction as the source resource.

```sql
CREATE TABLE search_documents (
    rowid INTEGER PRIMARY KEY AUTOINCREMENT,
    bank_id TEXT NOT NULL,
    resource_type TEXT NOT NULL CHECK (resource_type IN (
        'observation_chunk', 'entity', 'claim', 'artifact'
    )),
    resource_id TEXT NOT NULL,
    title TEXT NOT NULL DEFAULT '',
    body TEXT NOT NULL,
    metadata_text TEXT NOT NULL DEFAULT '',
    content_sha256 TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE (bank_id, resource_type, resource_id),
    FOREIGN KEY (bank_id) REFERENCES banks(id)
);

CREATE VIRTUAL TABLE search_fts USING fts5(
    title,
    body,
    metadata_text,
    content='search_documents',
    content_rowid='rowid',
    tokenize='unicode61 remove_diacritics 2'
);

CREATE TRIGGER search_documents_ai AFTER INSERT ON search_documents BEGIN
    INSERT INTO search_fts(rowid, title, body, metadata_text)
    VALUES (new.rowid, new.title, new.body, new.metadata_text);
END;

CREATE TRIGGER search_documents_ad AFTER DELETE ON search_documents BEGIN
    INSERT INTO search_fts(search_fts, rowid, title, body, metadata_text)
    VALUES ('delete', old.rowid, old.title, old.body, old.metadata_text);
END;

CREATE TRIGGER search_documents_au AFTER UPDATE ON search_documents BEGIN
    INSERT INTO search_fts(search_fts, rowid, title, body, metadata_text)
    VALUES ('delete', old.rowid, old.title, old.body, old.metadata_text);
    INSERT INTO search_fts(rowid, title, body, metadata_text)
    VALUES (new.rowid, new.title, new.body, new.metadata_text);
END;

CREATE INDEX idx_search_documents_resource
    ON search_documents(bank_id, resource_type, resource_id);
```

Every FTS query joins `search_fts.rowid` to `search_documents.rowid` and applies `bank_id = ?` before returning resources. Tests must prove that no caller can omit the bank at the repository API.

## 4. Canonical Claim Text

The search representation of a claim is deterministic:

```text
{subject canonical name} {predicate display phrase} {typed object display value}
```

It may include aliases in `metadata_text`, but aliases do not change the authoritative claim. Canonical text generation is versioned because changes require FTS/vector reindexing.

## 5. State Machines

### 5.1 Observation ingestion

```text
pending -> processing -> processed
                      -> partial
                      -> failed
pending/processing/processed/partial/failed -> quarantined
any retained state -> deleted
```

`deleted` is terminal for content access. Reingestion creates a new observation.

### 5.2 Claim lifecycle

```text
active -> contested
active -> superseded
active -> retracted
contested -> active
contested -> superseded
contested -> retracted
```

Every transition closes the old row’s `system_to` and inserts a successor claim row with a new ID and lifecycle. Changes to valid time, importance, subject, predicate, object, or polarity use the same close-and-insert rule. As-of queries therefore observe the lifecycle and content that existed at the requested system time.

### 5.3 Dream run

```text
queued -> leased -> running -> completed
                           -> awaiting_review -> completed
                           -> failed
                           -> canceled
leased -> queued          (lease expiry recovery)
running -> queued         (recoverable worker failure)
```

### 5.4 Proposal

```text
pending -> auto_eligible -> committed
pending -> review_required -> approved -> committed
                           -> rejected
pending/auto_eligible/review_required/approved -> stale
pending -> rejected
```

`stale` proposals may seed a new proposal but are never revived in place.

## 6. Repository Enforcement

DDL cannot express every domain invariant. Repository code must enforce:

- Global predicates (`bank_id IS NULL`) plus bank overrides resolve deterministically.
- Evidence offsets and excerpts match source content/chunks.
- Claim predicate exists or is created under conservative defaults.
- At least one supporting evidence row exists before an extracted claim becomes active.
- `created_by_run_id` belongs to the same bank.
- Claim group cardinality and conflict rules.
- Entity merge cycles are impossible.
- Relation cycles that violate semantics are rejected.
- Directives can only be written by privileged application services.
- Currentness is computed from predicate policy, evidence, validity, and query time; it is not persisted as authoritative claim state.
- Search documents and optional embeddings are updated or invalidated atomically with authoritative changes.
- Privacy deletion does not leak removed content into event payloads or retained artifacts.

These checks require unit and property tests. A direct SQL database is not a supported mutation interface.

---

## 7. Backup and Recovery

- Before migrations, create a SQLite online backup to a validated explicit path.
- WAL checkpoints run on controlled lifecycle boundaries, not on every write.
- `memorygraph doctor` checks foreign keys, integrity, FTS consistency, event watermarks, orphaned jobs, and optional vector index consistency.
- FTS and vector indexes are rebuildable from authoritative tables.
- Artifacts are rebuildable from claims.
- Interrupted commits rely on SQLite atomicity; interrupted external tasks rely on durable leases and idempotency.

---

## 8. Schema Review Questions Resolved

| Issue | Resolution |
|---|---|
| Cross-bank foreign keys | Composite `(bank_id, id)` foreign keys. |
| Mutable claims | Content immutable; only system interval/lifecycle closes under evented transaction. |
| Vector dependency | BLOB/index adapter is disposable and optional. |
| Natural-language search | Search documents plus optional query planner; no implication of deterministic semantic parsing. |
| Source traceability | Exact observation/chunk offsets and excerpts. |
| Model audit | Dream proposal model trace and run provider hash. |
| Rollback | Event-backed compensating transactions. |
| Summary drift | Artifacts cannot serve as source evidence and carry source watermarks. |
| Instruction poisoning | Privileged directives table separated from inferred claims. |
| Multi-valued predicates | Predicate cardinality controls conflict behavior. |

This schema is ready to translate into ordered migration files once the project specification is approved.
